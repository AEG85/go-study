Docker
— Возьмите за основу Golang-программу из предыдущего задания
— Необходимо внести следующие доработки: теперь мы сохраняем новых работников не в переменную, а в базу данных PostgreSQL, 
установленную на локальную машину в рамках урока по теме "Базы данных и PostgreSQL"
— Запустите новую написанную программу локально на машине через go run main.go (без Docker-контейнера). Откройте pgAdmin. 
Отправьте в вашу программу несколько HTTP запросов, оцените корректность её работы (создаются ли вообще новые работники в базе данных, 
корректно ли они из базы данных удаляются, корректно ли они все отображаются в HTTP ответах на GET /employees).
— Остановите работающую локально программу. Остановите работающую локально СУБД PostgreSQL.
— Запустите Docker-контейнер с PostgreSQL из Docker-образа от официального поставщика Postgres. Изнутри этого Docker-контейнера с 
PostgreSQL необходимо прокинуть на хост-систему 5432 порт, а также необходимо пробросить docker-volume, 
в котором PostgreSQL хранит все свои данные внутри Docker-контейнера, на локальную машину. Команду по запуску PostgreSQL внутри 
Docker-контейнера с пробросом 5432 порта и docker-volume'a необходимо вынести в отдельный Makefile таргет postgres-up.
— Попробуйте подключиться к этой PostgreSQL, запущенной внутри Docker-контейнера, из pgAdmin'a.
— Запустите Golang программу через go run main.go локально на вашей машине. Эта локально запущенная программа должна подключиться к PostgreSQL, 
запущенной внутри Docker-контейнера, через прокинутый 5432 порт.
— Протестируйте работу вашей программы, следите за корректностью сохраняемых в PostgreSQL данных.
— Не трогайте ваше Golang приложение, но остановите Docker-контейнер с PostgreSQL. После чего попробуйте дальше пользоваться вашим приложением, 
будто ничего не произошло. Какой вы видите результат? Есть ли какие-нибудь ошибки?
— Далее снова запустите PostgreSQL внутри Docker-контейнера make postgres-up.
— Сначала через pgAdmin, а после и через HTTP запрос GET /employees в ваше приложение удостоверьтесь, что все работники, 
которых вы сохранили в базу данных при предыдущем запуске контейнера с PostgreSQL, сохраняются и в этом запуске контейнера с PostgreSQL 
благодаря пророщенному docker-volume.
